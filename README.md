# Codyssey - Mini NPU Simulator

## 1. 개요

Codyssey 미션 3을 진행하면서 Python으로 패턴을 판별하는 Mini NPU 시뮬레이터를 구현했다.

입력 패턴과 필터의 같은 위치에 있는 값을 곱하고 더하는 MAC 연산으로 점수를 계산한다. 두 필터의 점수를 비교해 결과를 판정하고, 배열 크기에 따른 연산 시간을 측정했다.

Python 3.8 이상에서 실행할 수 있으며, 표준 라이브러리만 사용했다.

## 2. 파일 구성

| 파일 | 역할 |
|---|---|
| `main.py` | 메뉴, 입력 검증, JSON 분석, 결과 출력, 연산 시간 측정 |
| `npu.py` | MAC 점수 계산과 두 점수의 비교 및 판정 |
| `data.json` | 과제에서 제공한 크기별 필터와 테스트 패턴 |
| `README.md` | 실행 방법, 구현 내용, 결과 리포트 |

입출력과 실행 흐름은 `main.py`에서 관리하고, 두 모드에서 공통으로 사용하는 계산과 판정은 `npu.py`에 모았다.

## 3. 구현 내용

### 3.1. 사용자 입력 모드

3×3 필터 A와 B를 입력받아 저장한 뒤, 판별할 패턴을 입력받는다.

각 행에 숫자 세 개를 입력하도록 검사하며, 숫자 형식이나 열 개수가 잘못되면 해당 행을 다시 입력받는다. 입력이 완료되면 두 필터의 MAC 점수, 판정 결과, 평균 연산 시간을 출력한다.

### 3.2. JSON 분석 모드

`data.json`에서 5×5, 13×13, 25×25 필터와 패턴을 불러온다.

패턴 키가 `size_13_2`이면 크기 13을 추출해 `size_13` 필터를 선택한다. 배열의 행·열 수와 숫자 여부를 검사하고, 오류가 발생하면 해당 케이스를 FAIL로 기록한 뒤 다음 케이스를 처리한다.

필터 키와 정답은 다음 기준으로 정규화한다.

| 입력 라벨 | 표준 라벨 |
|---|---|
| `cross`, `+` | `Cross` |
| `x` | `X` |

각 패턴의 판정과 정답을 비교해 PASS 또는 FAIL을 출력한다. 마지막에는 전체 테스트 수, 통과 수, 실패 수와 실패 케이스별 사유를 출력한다.

### 3.3. MAC 연산과 판정

`npu.py`의 `mac()`은 이중 반복문으로 배열을 순회하면서 같은 위치의 값을 곱해 점수에 누적한다.

```python
# 같은 위치의 패턴 값과 필터 값을 곱해 점수에 더한다.
score += pattern[row][col] * kernel[row][col]
```

`decide()`는 두 점수 중 더 높은 쪽의 라벨을 반환한다. 부동소수점 오차를 고려해 두 점수 차이의 절댓값이 `1e-9` 미만이면 동점으로 보고 `UNDECIDED`를 반환한다.

필터 키와 expected는 `main.py`의 `normalize_label()` 함수에서
`Cross` 또는 `X`로 통일한다. 정규화 규칙을 한 함수에서 관리하여
필터 로드와 정답 비교에 동일한 기준을 적용한다.

### 3.4. 성능 측정

`main.py`의 `timecomplexity()`에서 MAC 함수를 100회 반복 호출하고, 전체 측정 시간을 반복 횟수로 나누어 평균 시간을 구한다.

시간 측정에는 `perf_counter()`를 사용하며, 입력·파일 읽기·출력은 측정 구간에서 제외한다.

사용자 입력 모드에서는 3×3을 측정한다. JSON 모드에서는 크기별 십자가 행렬을 준비해 3×3, 5×5, 13×13, 25×25의 평균 연산 시간과 필터 하나당 MAC 횟수인 N²을 출력한다.

## 4. 실행 방법

`main.py`, `npu.py`, `data.json`을 같은 폴더에 둔다. 터미널에서 해당 폴더로 이동한 뒤 실행한다.

```bash
python3 main.py
```

프로그램 실행 후 사용할 모드를 선택한다.

```text
1. 사용자 입력 (3×3)
2. data.json 분석
```

### 4.1. 사용자 입력 예시

1번을 선택하고 필터 A, 필터 B, 패턴 순서로 입력한다. 각 행을 입력한 뒤 Enter를 누른다.

**필터 A — 십자가**

```text
0 1 0
1 1 1
0 1 0
```

**필터 B — X**

```text
1 0 1
0 1 0
1 0 1
```

**입력 패턴 — X**

```text
1 0 1
0 1 0
1 0 1
```

실행 결과는 A 점수 1.0, B 점수 5.0이며 B로 판정된다. 이후 3×3 MAC 연산의 평균 시간이 출력된다.

패턴의 모든 값을 0으로 입력하면 두 점수가 모두 0이므로 판정 불가가 출력된다.

### 4.2. JSON 분석 실행

2번을 선택하면 `main.py`와 같은 폴더에 있는 `data.json`을 읽어 분석한다. 다운로드한 파일 이름이 `data (2).json`이면 `data.json`으로 변경한다.

각 케이스의 점수와 판정, PASS/FAIL을 출력한 뒤 크기별 성능 표와 전체 결과를 출력한다.

### 4.3. 입력 오류 및 동점 처리 확인

- 한 행에 `0 1`을 입력했을 때 열 개수 오류를 안내하고 같은 행을 다시 입력받았다.
- `a b c`를 입력했을 때 숫자 형식 오류를 안내하고 같은 행을 다시 입력받았다.
- 이후 정상적인 값을 입력하면 다음 행으로 진행했다.
- 패턴의 모든 값을 0으로 입력했을 때 두 필터의 점수가 모두 0이 되어 `UNDECIDED`로 판정됐다.

## 5. 결과 리포트

과제에서 제공한 `data.json`으로 실행한 결과, 전체 6건 중 3건 통과, 3건 실패로 집계됐다.

| 케이스 | Cross 점수 | X 점수 | 판정 | 정규화한 정답 | 결과 |
|---|---:|---:|---|---|---|
| `size_5_1` | 0.9 | 0.8999999999999999 | UNDECIDED | X | FAIL |
| `size_5_2` | 8.9 | 0.1 | Cross | Cross | PASS |
| `size_13_1` | 0.3 | 14.700000000000008 | X | X | PASS |
| `size_13_2` | 7.499999999999997 | 7.5 | UNDECIDED | Cross | FAIL |
| `size_25_1` | 4.9 | 4.899999999999999 | UNDECIDED | X | FAIL |
| `size_25_2` | 52.9 | 0.1 | Cross | Cross | PASS |

### 5.1. 실패 원인 분석

1. 여섯 패턴 모두 키에 적힌 크기와 실제 배열의 행·열 수가 일치했고, 해당 크기의 필터를 정상적으로 불러왔다.
2. 필터 키와 정답을 `Cross`, `X`로 정규화해 표기 차이로 인한 비교 오류를 방지했다.
3. `size_5_1`을 원본 십진수 기준으로 계산하면 두 필터 모두 0.90점이다. 실수 연산에서는 값을 누적하는 과정에서 끝자리에 차이가 발생했다.
4. 같은 방식으로 계산한 `size_13_2`는 두 필터 모두 7.50점이고, `size_25_1`도 두 필터 모두 4.90점이다.
5. 위 세 케이스는 두 점수의 차이가 `1e-9` 미만이므로 동점 정책에 따라 `UNDECIDED`로 판정했다.
6. 파일의 정답은 각각 X, Cross, X로 지정되어 있어 프로그램의 동점 판정과 달라 FAIL로 집계됐다.
7. 나머지 세 케이스는 점수가 더 높은 필터와 정답이 일치해 PASS로 처리됐다.

### 5.2. 성능 측정과 시간 복잡도

WSL Ubuntu 환경에서 JSON 분석 모드를 실행해 측정한 결과다. 측정 시간은 실행 환경과 실행 시점에 따라 달라질 수 있다.

| 크기 | 평균 시간(ms), 100회 | 필터 1개당 MAC 횟수 |
|---|---:|---:|
| 3×3 | 0.001130 | 9 |
| 5×5 | 0.002731 | 25 |
| 13×13 | 0.014581 | 169 |
| 25×25 | 0.042973 | 625 |

1. 크기에 따른 차이를 비교하기 위해 각 크기의 십자가 행렬을 미리 준비하고, MAC 함수 100회 호출 구간을 측정했다.
2. 필터 하나의 점수를 구할 때 N개 행에서 각각 N개 열을 방문하므로 MAC 연산은 N²번 수행된다.
3. 한 패턴을 판정하려면 두 필터를 적용하므로 총 MAC 횟수는 2N²이며, 시간 복잡도는 O(N²)이다.
4. 5×5에서 25×25로 커지면 MAC 횟수는 25배가 된다. 측정한 평균 시간은 0.002731 ms에서 0.042973 ms로 약 15.7배 증가했다.
5. 함수 호출과 반복문 제어에도 시간이 필요하므로 측정 시간의 비율이 MAC 횟수의 비율과 정확히 일치하지는 않는다.

### 5.3 대규모 행렬 처리 시 한계와 최적화 방안

1000×1000 행렬은 1,000,000개의 원소를 가진다.
필터 하나의 점수를 계산하려면 1,000,000회의 MAC 연산이 필요하며,
두 필터로 한 패턴을 판정하면 총 2,000,000회의 MAC 연산이 필요하다.
두 필터를 적용해도 상수 배수만 증가하므로 시간 복잡도는 O(N²)이다.

현재 구현은 Python의 중첩 반복문으로 원소를 하나씩 처리한다.
따라서 크기가 커지면 반복문 실행, 리스트 인덱싱, 수치 연산 비용이 누적된다.
패턴과 필터를 저장하는 공간도 각각 O(N²)이며,
Python의 중첩 리스트는 원소 외에 참조와 리스트 객체의 메모리도 사용한다.
JSON 로드 과정에서도 원본 데이터와 변환된 배열이 함께 존재하면
일시적인 메모리 사용량이 증가할 수 있다.

우선 불필요한 배열 복사를 줄이고, 같은 필터를 반복 생성하지 않도록 한다.
이후 1차원 배열로 표현하여 중첩 인덱싱을 줄이는 방법을 검토할 수 있다.
다만 Python 리스트를 평탄화해도 숫자 값 자체가 연속 저장되는 것은 아니므로,
속도 개선 여부는 변환 비용을 포함한 실제 측정으로 확인해야 한다.
메모리 절감이 필요하면 표준 라이브러리의 array도 검토할 수 있다.

블록화는 데이터를 작은 구간으로 나누어 캐시 활용을 개선하는 방법이다.
다만 현재 MAC은 각 원소를 한 번씩 순서대로 읽으므로,
데이터 재사용이 많은 행렬 곱셈만큼의 효과를 기대하기는 어렵다.
독립된 패턴이 많다면 multiprocessing으로 작업을 분산할 수 있지만,
프로세스 생성과 데이터 전달 비용도 함께 비교해야 한다.

위 내용은 대규모 입력에 대한 예상 분석이며,
1000×1000 실행 시간이나 최적화 효과를 실제로 측정한 결과는 아니다.

### 5.4 CPU와 NPU의 연산 방식 및 병목

CPU는 다양한 프로그램과 복잡한 제어 흐름을 처리하는 범용 프로세서이다.
CPU도 여러 코어와 SIMD 명령으로 병렬 처리가 가능하지만,
현재 Python 코드는 중첩 반복문으로 MAC을 순차 수행한다.
이 구현에서는 반복문과 객체 접근 비용이 실행 시간에 영향을 준다.

NPU는 신경망에서 반복되는 MAC과 행렬 연산을 효율적으로 처리하도록
다수의 연산 장치와 데이터 이동 구조를 갖춘 전용 프로세서이다.
여러 MAC을 병렬 수행하여 큰 연산량을 처리하는 데 유리하다.

하지만 NPU도 입력과 가중치를 충분히 빠르게 공급받지 못하면
연산 장치가 데이터를 기다리는 메모리 대역폭 병목이 발생한다.
작은 작업에서는 장치로 데이터를 전달하고 실행을 준비하는 비용이
실제 계산 시간보다 크게 작용할 수도 있다.

CPU에서는 불필요한 Python 반복 처리와 데이터 복사를 줄이고,
가능한 환경에서는 SIMD나 병렬 처리를 활용하는 방향을 검토할 수 있다.
NPU에서는 데이터를 장치 내부 메모리에서 재사용하고,
작업을 묶어 전송 및 실행 준비 비용을 줄이는 방향이 중요하다.

이번 프로그램은 CPU에서 실행되는 MAC 원리 시뮬레이터이며,
실제 NPU의 병렬 실행이나 하드웨어 성능을 재현하지는 않는다.
